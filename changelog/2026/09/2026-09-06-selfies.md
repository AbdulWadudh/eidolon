# Selfies: real image generation through ComfyUI and PuLID

**Date:** 2026-09-06
**Scope:** apps/conductor, apps/canvas, packages/config, packages/protocol

## What it was

Image generation existed as a shape, not a feature. `request_image` sent a
`painting` status, posted a hardcoded SDXL-Turbo workflow at ComfyUI, ignored
the result entirely, then emitted a 60-byte base64 `image_preview` and an
`image_ready` pointing at a mock backdrop URL. The workflow named
`sd_xl_turbo_1.0_fp16.safetensors`, which is not the checkpoint installed, so
even the queue call would have been rejected on validation. On the client the
gallery button was wired to a no-op and no message could carry an image.

## What it is

Tapping the gallery button asks the character for a photo. The character sends
one back, in the chat, of the same person every time.

**The face is bootstrapped once and then reused.** PuLID needs a reference face,
and no character had one. The first request asks the LLM to turn the character's
written persona into a physical description, generates a plain portrait from it,
and stores that as the character's avatar in S3. Every later photo runs
`ApplyPulid` against it, so identity survives across scenes, outfits, lighting
and restarts. The description is stored on the character too — regenerating it
per process gave Emma brown eyes one run and blue the next, which contradicted
the face PuLID was matching.

**The scene comes from the conversation.** `image.scene` turns the last turns
plus whatever was asked for into an image prompt. The physical description is
prepended in code rather than asked for again, since asking produced it twice in
the same prompt.

**Two prompts, one catalogue.** `image.appearance` and `image.scene` join the
other eight in `@eidolon/config`, editable in one place like the rest.

## The roleplay model will not write prompts

Asked plainly for an image prompt, the model replied in character:

```
FULL PROMPT:
*looks up from my phone with a smile, seeing it's you* Hey there! How was your day?
```

It is tuned to be a person, and a bare instruction reads as dialogue. Two things
fix it: a system message that frames the job as writing prompts and forbids
first person and asterisks, and a guard that checks the output actually looks
like a prompt before trusting it. `isPromptLike` rejects asterisks, quotes,
questions and first or second person; anything rejected falls back to the
reader's own words for the scene, and to a fixed description for the appearance.
The generation never fails because the model went method.

## The pipeline

`services/comfy-workflow.ts` builds the graph — twelve nodes with PuLID, seven
without, so a character with no face reference yet still renders. Sampler
settings come from `IMAGE` in the config: RealVisXL V5.0 Lightning at 6 steps and
CFG 2, which is what a Lightning checkpoint wants, against the old stub's 25
steps and CFG 7.

`services/comfyui.ts` was rewritten from a fire-and-forget POST into a real
client: upload the face reference to ComfyUI's input directory, queue the graph,
poll `/history/{prompt_id}` until it completes, pull the PNG from `/view`, and
hand back bytes. Failures are typed — `ComfyUnavailableError` when the server is
not there, `ComfyGenerationError` when the graph fails — so the socket can say
"No camera on this side" rather than dropping a mock image into the transcript.

## Timings, measured

| | |
|---|---|
| plain SDXL portrait | 3.9s |
| first PuLID run | 48.1s |
| warm PuLID run | 5.3s |
| full round trip, first ever request | 16.5s |
| full round trip, warm | 5.5s |

The 48s is PuLID, EVA-CLIP and InsightFace loading into VRAM on first use. It is
paid once per ComfyUI process, and the first request for a character pays the
face bootstrap on top, which is why the first round trip is 16.5s and every one
after is about five.

## Client

`messages.image_url` and `characters.appearance` are new columns, both added
through the same idempotent `PRAGMA table_info` check as `audio_duration`.
`image_ready` appends an assistant message carrying the URL, and the transcript
returns it, so photos survive a reload the same way voice notes now do.

`MessageImage` renders inside the bubble at the generated aspect ratio, with the
theme's radius and card border, and a shimmer underneath until the bitmap
arrives. It uses `expo-image` for disk caching and a cross-fade — added on
request, at the SDK-pinned `57.0.4`.

## Evidence

- Generated and inspected four images end to end: a plain portrait, a PuLID
  transfer to a rooftop at night, a warm PuLID run in a car, and a full socket
  round trip to a bookshop. Same face in all of the PuLID ones.
- `request_image` over the socket returned
  `status: painting → painting → image_ready 9:16 → status: idle`, with a real
  RustFS URL that fetches anonymously.
- `bun run test` — 273 pass / 0 fail. Lint 173 files clean, typecheck clean, size
  gate clean.

## Still open

- `image_preview` is defined in the protocol and never sent. ComfyUI streams
  progress over its own websocket; the conductor polls history instead, so there
  is no step counter behind "Taking the photo".
- Nothing cancels a queued ComfyUI job. `interrupt` aborts the wait, not the
  work.
- The photo is not tappable. There is no full-screen viewer.
- `forgetCharacter` leaves the avatar and appearance in place, so resetting a
  character's memory keeps their face. That is deliberate, but it means there is
  no way to ask for a different face short of clearing the columns by hand.
